        2. Visual style (tokens)

        All values are in tokens/tokens.css. Use the variables, not raw hex values.

        Token Hex Use

        --tm-sand-deep #EFD9C2 Illustration panels

        --tm-ink #1F3A5F Text, “Live” label, navy panels
        --tm-muted #3F5878 Secondary text
        --tm-terracotta #B14E2E Primary buttons, “Selected” badge and ring, focus ring (white text ≈ 5:1)
        --tm-sun / --tm-sea #E9A15A / #2C5C8A Illustration only (sea also for the demo band)
        --tm-peach #F2B98A DEMO ribbon, “Demo price” label
        --tm-line #EADFD1 Dividers, card borders
        --tm-input-border #8C8277 Input borders (≥ 3:1)
        --tm-success #2F6B4F Within budget, done, “Taxes and fees included”
        --tm-danger / --tm-danger-bg / --tm-danger-text #B3261E / #FCE8E6 / #8C1D18 Errors, Over budget, Missing chips, “Unknown” amounts
        --tm-warning-bg / --tm-warning-text #FDF0D2 / #6B4A0B Uncertain, warnings, MOCK ribbon
        --tm-unavailable-bg / --tm-unavailable-text #E2DACE / #4F5B66 “Unavailable” and “Unknown” labels
        --tm-disabled #7A6E64 Loading / disabled primary button

        Type: Fraunces 600/800 (headings, prices) + Figtree 400/500/700. Scale: Display 48–88 · H1 36–56 · H2 32 · H3 22 · Body L 18 · Body 16 · Label 15 bold · Small 14 · Eyebrow 13 bold caps. Shape: fields 54 px, radius 14 · buttons 56 px, radius 16 · cards 24 · panels 28 · pills 999. Spacing 4/8/12/16/24/32/48/64. Page max 1240 px; side padding clamp(16px, 4vw, 48px). Money: always two decimals and a thousands separator ($1,140.00, contract §2). Estimates start with ~. Unknown shows the word Unknown or “—”, never $0.00. An explicit 0 estimate (a free activity) shows $0.00 with the Estimate label. Times: offer timestamps are UTC in the contract; show them as Tue, 10 Nov, 07:00 UTC until local times are available (see §10).

        4. Responsive behaviour

        • Built at 1440 px; checked at 390 px. No horizontal scrolling.
        • Two-column layouts stack below ~960 px. On Your trip and Demo trip the budget and expenses column moves above the offers and itinerary.
        • The decorative sun in the trip banner is hidden below 600 px so the title stays readable.
        • Headings scale with clamp(); body text never below 14 px. Top bars wrap onto two rows on phones.

        5.5 Plan a trip (/trip-planner)

        UI field Request field (v0.4) Rule Client error
        From (select) departure_city canonical supported label “Choose where you leave from.”
        To (select) + swap destination_city supported, ≠ departure “Choose your destination.” / “Pick a different city from your departure.”
        Start date start_date (YYYY-MM-DD) after today's UTC date “Choose a start date.” / “Start date must be in the future.”
        Return date return_date 1–7 nights after start “Choose a return date.” / “Return date must be after the start date.” / “Trips can be up to 7 nights.”
        Stay (read-only) – green 1–7, red otherwise –
        Adults stepper adults (integer) 1–4 helper “1–4 adults. Children aren't supported yet.”
        Budget (USD) budget_usd (number) > 0, whole trip, all adults “Enter your total budget.” / “Budget must be more than $0.00.”
        • No currency selector, one-way switch or user id (contract §3).
        • City list: the prototype's six cities are labelled “Sample cities for testing (mock)” until provider coverage is verified (FE-02).
        • Summary when valid: “Istanbul → Rome · 5 nights · 2 adults · $1,500.00”.
        • Server errors on this screen: 400 UNSUPPORTED_LOCATION → banner “We can't price this route yet”; 400 INVALID_TRIP_DATES → “Check your dates”; 422 VALIDATION_ERROR → banner + each details.fields[] message under the matching field.
        • While the request is in flight the button is disabled and reads “Sending…”; a second submit is impossible.
        • States: live · errors · filled · submitting · unsupportedLocation · invalidDates · serverValidation.

        5.6 Building your trip (loading and request errors)

        Five steps advance on a timer (the API returns one response; there are no progress events). When the response arrives: success → See my trip; error → the matching panel:

        HTTP / code (v0.4) Title Actions
        502 AI_GENERATION_FAILED We couldn't build your plan Try again · Edit trip
        504 GENERATION_TIMEOUT This is taking too long Try again · Edit trip
        429 RATE_LIMITED Too many requests right now Try again (disabled until Retry-After, e.g. “Try again in 30 s”) · Edit trip
        503 PROVIDER_UNAVAILABLE The planning service is unavailable Try again · Edit trip · Open a demo trip
        500 INTERNAL_ERROR Something went wrong on our side Try again · Edit trip
        401 UNAUTHORIZED Please sign in again Sign in · Edit trip

        Each panel shows code · Reference {request_id} in small text. Never auto-retry generation (contract §5). Frontend transport allowance is 70 s. States: live · searching · done · aiFailed · timeout · rateLimited · providerUnavailable · internalError · unauthorized.

        5.7 Your trip (/results) — contract mapping

        States = the six v0.4 fixtures (?fixture=): within-budget · over-budget · partial-prices · no-prices · known-minimum-over-budget · unknown-taxes. Toggle the MOCK ribbon with fixtureBanner.

        Screen element v0.4 field(s) Display rule
        MOCK ribbon fixture manifest.data_mode = structural_mock Shown whenever fixture data is rendered online; never for real API data
        Banner: route trip.departure_city, trip.destination_city “Istanbul → Rome”
        Banner: meta trip.start_date, return_date, nights, adults, budget.budget_usd “10 – 12 November 2026 · 2 nights · 2 adults · Budget $1,500.00”
        “No live prices” banner live_integration_status = no_price With Try again
        Warnings list warnings[].code, .message Short title per known code + API message; unknown codes show “Note.” + message
        Flights block travel_options.flights.status, .offers[] live → offer cards; unavailable → “—” card
        Flight card airline, departure_airport_code → arrival_airport_code, outbound_departure_at, return_departure_at, adults, price.amount_usd, taxes, source, retrieved_at Coverage “Total for N adults”
        Hotel card name, area (null → “Area not provided”), check_in, check_out, occupancy_adults, room_qty (null → “rooms not provided”), price, taxes, source, retrieved_at Coverage “Total stay, N adults”
        Selected offer budget.selected_flight_offer_id, selected_hotel_offer_id Terracotta ring + “Selected”, listed first; the UI never chooses
        Taxes line taxes.status / additional_amount_usd included → “Taxes and fees included” (green) · additional_known → “+ $50.00 taxes and fees (added in the budget)” · unknown → “Taxes and fees unknown” (red)
        Price label price.kind = provider Live (online) / Demo price (demo)
        Day card itinerary[] (date) “Day N” + “Tuesday 10 November”; exactly nights + 1 days
        Activity row activities[].order, name, area, description, cost Numbered by order; cost: estimate → “~40.00” /“0.00” + Estimate; unknown → “Unknown”
        Empty day empty_day_reason (first/last day only) Sand box with the reason text
        Budget check status budget.status Within/Over/Uncertain pill + reason (see below)
        Budget rows budget_usd, provider_subtotal_usd, estimated_subtotal_usd, projected_total_usd “Live prices”, “Estimates (~)”, projected total or “Not calculable” when null
        Missing chips budget.missing_categories[] Flights, Hotel, Taxes and fees, Activities, Food, Local transport
        Notes budget.notes[] Small text under the totals
        Itemized expenses budget.cost_items[] (category, label, amount_usd, kind, basis, source_offer_id, activity_ref) Grouped: Flights · Hotel · Taxes and fees · Activities · Food · Local transport; each row shows a readable label, kind label, amount (or Unknown) and basis

        Status reasons: within → “The projected total fits your budget. Prices can still change.” · over with total → “The projected total is $X over your budget.” · over with total null (known minimum) → “Live prices alone already exceed your budget, before the missing costs are added.” · uncertain → “Some costs are unknown, so we can't say whether this trip fits your budget.” Footnote: “An estimate, not a booking price. Totals are calculated by TravelMate, not by the AI.” The UI never recalculates totals or status; it renders the backend values.

        7. Accessibility

        Labels on every field; errors via aria-describedby and aria-invalid; error banners role="alert", progress and warnings role="status"; icon-only buttons have aria-label; toggles use aria-pressed; selected offers say “selected” in their accessible name; visible 3 px focus ring; contrast ≥ 4.5:1 text, ≥ 3:1 borders; status always written in words; touch targets ≥ 44 px; one <h1> per screen; spinner animation stops under prefers-reduced-motion.

        8. Copy rules

        Plain and short; sentence-case buttons; money per §2; never promise a booking or guaranteed price; never present AI or demo prices as live.

        10. Open questions and flagged contract items (for Nasrawy)

        Contract v0.4 — please confirm or change:

        1. No day title and no time of day. v0.4 activities have only order; the design numbers them and titles each day with its date. Add an optional title/time_of_day if wanted.

        3. Times are UTC only. Flight times show “07:00 UTC”; travellers expect local airport time. Consider adding local times or the airport timezone.
        4. Food and local transport stay Unknown in real output until the estimation policy is approved (fixtures show example estimates).
        5. Supported cities and provider names are still pending; the form shows a mock list.
